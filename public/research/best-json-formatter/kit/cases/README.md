# Test cases

Paste any of these into a JSON formatter by hand. Generated by `node cases.mjs`.

## Data safety (valid JSON; the formatted output must keep the same data)

| File | Checks |
|---|---|
| `data-big-integer.json` | 12345678901234567890 stays exactly that |
| `data-max-safe-plus-one.json` | 9007199254740993 is not rounded to 9007199254740992 |
| `data-long-decimal.json` | a decimal with more digits than a double keeps them |
| `data-number-spelling.json` | 1.0, 1.50, 1E+2, -0 and 0.5e1 keep their spelling |
| `data-huge-exponent.json` | 1e400 and 1e-400 are not turned into Infinity, 0, null or an error |
| `data-duplicate-keys.json` | both members of a duplicated key are kept |
| `data-key-order.json` | keys keep their order (JavaScript objects move integer-like keys first) |
| `data-unicode.json` | emoji, CJK, right-to-left text, combining marks, U+2028, escaped characters and a lone surrogate survive |
| `data-escapes.json` | every JSON escape keeps its meaning |
| `data-proto-key.json` | a "__proto__" key, a "constructor" key and an empty key survive |
| `data-top-level-scalar-1/2/3.json` | a bare string, number and null are accepted (all valid JSON) |
| `data-deep-nesting.json` | 2,000 nested arrays format, or are refused with a clear message, without freezing the tab |
| `data-long-string.json` | a single 1,000,000-character string is kept intact |
